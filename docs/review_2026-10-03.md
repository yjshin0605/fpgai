# 2026-10-03 수정본 검토

## 범위

제공된 Verilog 7개와 후단 모듈 사양서를 검토했습니다. RTL·DOCX 원문은 변경하지 않았습니다.
Icarus Verilog 12.0에서 컴파일 및 아래의 제한된 합성 입력 검사를 수행했습니다.
단일 레코드 검사 통과는 전체 골든 일치, 분류 정확도, 100 MHz 타이밍 충족을 의미하지 않습니다.
첨부된 Vivado 합성 원본 보고서와 앞단/PS 구현이 없어 해당 사항은 재검증하지 못했습니다.

## 1. 연속 레코드에서 결과 혼합과 누락 — 높음

위치: `spec_feat.v`의 `regs_flat`, `tr_done`/`eh_done` 결합 로직.
완료 여부만 1비트로 저장하고 각 레코드의 특징을 큐에 보관하지 않습니다.
포락선 두 번째 결과가 첫 번째 궤적 결과보다 먼저 나오면 첫 번째 분포 결과가 덮어써집니다.

재현: FFT는 레코드당 127×256빈, DC는 16,384샘플을 각각 클럭마다 1개씩 두 레코드 연속 입력했습니다.
모든 프레임은 활성, FFT는 DC 빈에만 값 16,384, 나머지는 0입니다.
DC I는 첫 레코드 1,024, 두 번째 2,048이고 Q와 NORM_SH는 0입니다.

- 기대: 결과 2회, 각 mean_q8=256, 512.
- 관측: 첫 결과의 mean_q8=512, 전체 결과는 1회만 발생.
- 첫 궤적 결과에 두 번째 분포 결과가 결합되고, 두 번째 결과를 위한 완료 표시가 남지 않습니다.

권장: 레코드 ID와 함께 두 갈래 결과를 각각 FIFO/핑퐁 저장하고 동일 ID끼리 결합하거나, 한 레코드 결과를 회수하기 전 다음 입력을 금지하는 명확한 제어를 구현합니다.
현재 앞단이 항상 한 레코드씩 직렬로 공급한다면 이 재현 조건은 피할 수 있지만, 후단 자체가 연속 스트림을 안전하게 처리한다고 볼 수 없습니다.
이 결합 구조의 취약점은 이전 버전에도 있던 부분입니다.

## 2. AXI 쓰기 마스크 무시 — 중간

위치: `spec_feat_axi.v`의 `clr_done`, `set_sh`, `set_skip`.
`s_axi_wstrb`를 선언만 하고 쓰기 반영 조건에 사용하지 않습니다.

- 0x50에 WDATA=5, WSTRB=0000으로 쓰면 NORM_SH가 0에서 5로 바뀝니다.
- 0x54에 WDATA=24, WSTRB=0010으로 쓰면 하위 바이트가 비활성인데도 SKIP_FR가 24로 바뀝니다.

권장: 현재 세 레지스터의 유효 필드는 하위 바이트에 있으므로 WSTRB[0]을 반영합니다.
현재 RTL 시험에서는 설정 쓰기를 정렬된 32비트 전체 쓰기(WSTRB=1111)로 제한해야 합니다.
기존 done clear에도 같은 제약이 있었고, 이번에는 새 설정 레지스터에도 적용됩니다.

## 3. 계산 중 리셋하면 히스토그램 잔존 — 중간

위치: `traj_rec.v`의 `hist` 초기화 및 PASS/SCANH 상태.
히스토그램은 initial에서만 초기화하고, 정상 처리 시 SCANH에서 지웁니다.
PASS 도중 rstn을 내리면 FSM은 초기화되지만 누적된 hist는 남습니다.

재현은 실행 시간을 줄이기 위해 N_FR=4, REP_MIN=REP_MAX=2로 수행했습니다.
피크 42에 두 번 누적된 시점에 리셋하고 이후 네 프레임을 모두 invalid로 입력했습니다.
관측값은 n_active=0, hmax=2로, 기대 hmax=0과 다릅니다.
같은 hist 초기화 경로를 쓰는 기본 설정에서도 계산 중 리셋에 대한 대책이 필요합니다.

권장: 리셋 후 256빈을 지우는 초기화 상태와 그동안의 입력 제어를 추가합니다.
이 문제는 이전 버전에도 존재했습니다. 정상 레코드 완료 후의 리셋과는 구분해야 합니다.

## 4. 기존 통합 테스트벤치와 신규 인터페이스 불일치

`tb_spec_feat_axi.v`를 신규 RTL과 컴파일하면 env_tdata/env_tvalid/env_tready 포트 없음으로 오류 3개가 발생하고, FFT 32→64비트 폭 경고가 발생합니다.
기존 `tb_spec_feat_all.v`도 동일한 구형 인터페이스를 사용합니다.
사양서의 `tb_spec_feat_smoke.v`는 첨부되지 않았습니다.
새 포트·태그·프레임 invalid·NORM_SH를 반영한 테스트벤치와 새 기대값이 필요합니다.
기존 골든 데이터에서 활성 판정과 정규화 위치까지 바뀌었으므로, 단순 포트 이름 교체로 기존 144/144 검증을 재사용할 수 없습니다.

## 5. 사양서와 주석 정정 사항

- env=max+3/8×min의 실수 근사식은 최대 양의 상대오차가 약 6.80%입니다. 문서의 ‘최대 약 4%’ 및 ‘칸을 바꾸지 않는다’는 표현은 맞지 않습니다. I=950, Q=350에서 RTL 근사는 1,080(빈 1), sqrt 기준은 약 1,012.42(빈 0)입니다. 근사식을 사용하는 것 자체가 오류라는 뜻은 아니며, 골든 모델도 동일한 정수 연산을 사용해야 합니다.
- `cordic_mag.v` 머리 주석의 ‘x>>>1, 16비트’와 max_v의 ‘65535’는 현재 기본값인 OUT_SHIFT=4, OUT_W=18(최대 262143)과 다릅니다.
- `spec_feat_axi.v`의 특징 범위는 0x08~0x48이며, 주석의 0x4C는 잘못된 끝 주소입니다.
- `traj_frame`과 `traj_rec`의 개별 기본 MAG_W는 16입니다. 상위 spec_feat에서 18로 override하므로 현재 상위 연결은 맞지만 단독 인스턴스화할 때 주의해야 합니다.
- AXI/PL 동일 클럭은 ‘권장’보다 필수 연결 조건으로 명시해야 합니다. 현재 CDC 로직은 없습니다.
- shadow는 새 결과가 나올 때마다 갱신되므로 PS가 읽는 동안 다음 레코드가 완료되면 값이 섞일 수 있습니다. 한 레코드씩 처리하거나 결과 잠금/이중 버퍼가 필요합니다.
- busy는 traj_rec 계산 FSM만 표시합니다. 입력을 모으는 시간과 포락선만 처리되는 시간에는 0일 수 있어 전체 완료 판단에 사용하면 안 됩니다.
- PS가 DDR의 원시 입력에서 구한 최대값과 DC 제거 출력의 최대값은 일반적으로 같지 않습니다. NORM_SH 산정에 사용하는 신호 지점·DC 상태·전부 0인 입력 처리 규칙을 앞단/PS와 확정해야 합니다. PS 구현이 없어 이번에는 오동작으로 단정하지 않았습니다.

## 통과한 검사와 한계

단일 레코드에서 FFT valid에 빈 구간을 넣어도 natural-order 피크 변환과 CORDIC 태그 연결을 거쳐 기대 결과가 나왔습니다.
확인값: n_active=127, n_pairs=126, n_zero=126, rep_max=125, rep_lag=2, bw_sum=127, mean_q8=256.
이는 제한된 합성 입력 검사이며 모든 특징·신호 종류·AXI 트랜잭션을 포괄하지 않습니다.

## 재현 명령

Icarus Verilog가 설치된 환경에서 저장소 루트 기준으로 실행합니다.
출력의 WSTRB/CONTINUOUS/RESET 행은 현재 결함을 관측하기 위한 진단값입니다. 종료 코드 0만으로 문제가 해결됐다고 판단하지 마세요.

```sh
iverilog -g2012 -Wall -s tb_review -o /tmp/fpgai_review.vvp tests/review/tb_review.v cordic_mag.v traj_frame.v traj_rec.v env_detect.v env_hist.v spec_feat.v spec_feat_axi.v
vvp /tmp/fpgai_review.vvp
iverilog -g2012 -s tb_reset -o /tmp/fpgai_reset.vvp tests/review/tb_reset.v traj_rec.v
vvp /tmp/fpgai_reset.vvp
```
