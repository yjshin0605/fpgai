# FPGAI 특징 추출 RTL

2026-10-03 수정본입니다. FFT 출력과 DC 제거 출력을 받아 특징 17개를 계산합니다.
최상위 모듈은 `spec_feat_axi`입니다. 업로드된 RTL과 사양서는 제공받은 원본을 유지했습니다.

## 현재 버전 연결

Design Sources에 다음 7개 파일을 추가합니다.

- `cordic_mag.v`
- `traj_frame.v`
- `traj_rec.v`
- `env_detect.v`
- `env_hist.v`
- `spec_feat.v`
- `spec_feat_axi.v`

FFT 입력은 64비트 데이터(실수 `[24:0]`, 허수 `[56:32]`)와 `fft_tuser[16:0]`, `fft_tlast`를 사용합니다.
빈 순서는 natural order이며 내부에서 피크 번호에 fftshift를 적용합니다.
포락선 갈래에는 DC 제거 직후의 정규화 전 I/Q 36비트를 연결합니다.
`clk`와 `s_axi_aclk`는 반드시 같은 클럭으로 연결해야 합니다. 별도 클럭 간 동기화 회로는 없습니다.

| 주소 | 내용 |
|---|---|
| 0x00 | STATUS: bit0 done, bit1 궤적 계산 busy |
| 0x04 | 완료 레코드 수 |
| 0x08–0x48 | 특징 17개 |
| 0x50 | NORM_SH: signed 5비트 포락선 배율 |
| 0x54 | SKIP_FR: 앞쪽 궤적 프레임 제외 기준 |

상세 설명은 [후단 모듈 사양서](<후단(특징추출) 모듈 사양서.docx>)를 참고합니다.

## 검증 상태와 알려진 문제

컴파일과 단일 합성 입력 레코드 검사는 통과했습니다. 새 골든 모델과의 전체 값 비교, Vivado 재합성 및 보드 검증은 이번 검토에서 수행하지 않았습니다.

**연속 입력에서 레코드 결과 혼합·누락, WSTRB 무시, 계산 중 리셋 후 히스토그램 잔존이 재현되었습니다.**
원인, 재현 결과, 개선 방향은 [코드 검토 기록](docs/review_2026-10-03.md)에 정리했습니다.

수정 전 시험은 한 레코드를 입력하고 done 확인 → 특징 읽기 → done 지우기를 마친 뒤 다음 레코드를 시작하는 방식으로 제한합니다.
NORM_SH와 SKIP_FR는 이전 레코드 처리가 완전히 끝난 뒤, 새 입력 전에 설정하고 레코드 처리 중에는 변경하지 않습니다.
busy=0은 입력 수집이나 전체 처리가 끝났다는 뜻이 아닙니다.
이 순서 제한은 연속 입력 문제를 피하기 위한 임시 조건이며, 리셋 문제까지 해결하지는 않습니다.

## 이전 버전 자료

기존 `tb_spec_feat_axi.v`, `tb_spec_feat_all.v` 및 다른 기존 테스트벤치와 `특징추출_RTL_완료보고.md`, `golden_archive/`는 이전 인터페이스 자료입니다.
특히 기존 통합 테스트벤치는 32비트 FFT·`env_tdata` 포트를 사용하므로 현재 RTL에 그대로 연결하면 컴파일 오류가 납니다.
이전 144/144 통과 결과를 현재 버전의 검증 결과로 해석하면 안 됩니다.
사양서에 언급된 `tb_spec_feat_smoke.v`는 이번 첨부에 포함되지 않았습니다.

이전 골든 ZIP 복원:

```sh
python golden_archive/restore.py
```
